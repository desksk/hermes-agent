# AISTOC Agent 升级与回滚说明

## 1. 基本原则

- 应用内自动更新已关闭，不连接官方更新通道。
- 升级 = 用新版安装包**覆盖安装**；回滚 = 用旧版安装包**覆盖安装**。
- 升级和回滚都**不要先卸载**，否则可能触发卸载向导中的数据删除选项。
- 覆盖安装只替换安装目录 `%LOCALAPPDATA%\Programs\AISTOC Agent`，用户数据目录 `%APPDATA%\AISTOC Agent` 不动。
- 数据目录是升级和回滚前唯一需要重点保护的内容。

## 2. 版本与校验文件

### 2.1 版本号与文件名

- 定制版本号规划为 `1.0.0+aistoc.<构建号>`。
- 安装包文件名：`AISTOC-Setup-<version>-x64.exe`。
- 当前开发构建为 `AISTOC-Setup-0.0.0-x64.exe`；实际版本以产物文件名和 `build-info.json` 中的 `artifact` 为准。

### 2.2 build-info.json

每次构建由校验脚本在 `apps/desktop/release` 下生成，主要字段：

| 字段 | 含义 |
|---|---|
| `artifact` | 安装包文件名（含版本号） |
| `bytes` | 安装包字节数 |
| `sha256` | 安装包 SHA256 |
| `upstream_commit` | 构建时的上游 git commit |
| `built_at` | 构建时间（ISO 8601） |
| `python` | 构建所用 Python 版本 |

`build-info.json` 用于确认“这个安装包是哪一个版本、基于哪个上游 commit、何时构建”。应用内“设置 → 关于”会显示桌面端版本号，可与安装包文件名交叉核对；上游 commit 以 `build-info.json` 为准。

### 2.3 SHA256SUMS.txt

内容为一行：`<sha256>  <安装包文件名>`，用于分发后校验文件完整性。

### 2.4 核对方法

在安装包所在目录打开 PowerShell：

```powershell
Get-Content .\build-info.json | ConvertFrom-Json
Get-Content .\SHA256SUMS.txt
Get-FileHash .\AISTOC-Setup-<version>-x64.exe -Algorithm SHA256
```

`Get-FileHash` 的输出应与 `SHA256SUMS.txt` 以及 `build-info.json` 中的 `sha256` 一致。不一致的安装包不得用于升级或回滚。

> 说明：当前 `aistoc/build/verify-installer.ps1` 仍在完善中。正式分发前应确认每个安装包都附带这两个文件；缺失时向构建人员索取，不要仅凭文件名判断版本。

## 3. 升级流程

1. **获取新版三件套**：新版安装包、`build-info.json`、`SHA256SUMS.txt`。
2. **核对版本与哈希**：按 2.4 节确认安装包完整，确认 `artifact` 和版本号符合预期。
3. **备份用户数据**：按《安装说明》第 6 节备份 `%APPDATA%\AISTOC Agent`。升级原则上不动数据目录，备份用于应对异常情况。
4. **完全退出程序**：包括托盘中的后台进程，确认任务管理器中没有 AISTOC Agent 相关进程。
5. **运行新版安装包**：双击 `AISTOC-Setup-<新版本>-x64.exe`，UAC 提示选择“是”。
6. **覆盖安装**：安装程序会安装到原安装目录，无需先卸载旧版。等待完成并启动。
7. **升级后检查**：
   - “设置 → 关于”显示的桌面端版本与新版安装包版本一致；上游 commit 记录在新版 `build-info.json` 中，一并归档。
   - 原有模型配置仍在，不需要重新走首启向导。
   - 历史会话、记忆和技能列表可正常打开。
   - 发起一次对话，确认模型端点连通。

如果升级后重新出现首启向导，通常说明用户数据目录未被正确识别。先退出程序，检查 `%APPDATA%\AISTOC Agent` 是否存在、当前 Windows 账号是否与安装时一致，不要急于重新配置覆盖原数据。

## 4. 回滚流程

回滚的前提是保留旧版安装包及其校验文件。建议每个发布版本都归档，不要只保留最新版。

1. **找到旧版三件套**：旧版安装包、对应的 `build-info.json`、`SHA256SUMS.txt`。
2. **核对旧版哈希与版本**：按 2.4 节校验。
3. **备份当前数据**：回滚前必须备份 `%APPDATA%\AISTOC Agent`。
4. **完全退出程序**：包括托盘进程。
5. **运行旧版安装包**：双击 `AISTOC-Setup-<旧版本>-x64.exe`，UAC 选择“是”，覆盖安装到同一目录。
6. **启动并检查**：关于页版本回到旧版；模型配置和历史会话可读；发起一次对话验证连通性。

**数据兼容性注意**：安装包本身不会改动或降级用户数据。但新版运行期间可能已经写入新格式的配置或会话文件，旧版未必能完整读取。因此：

- 回滚前必须备份数据目录。
- 若旧版启动后配置丢失、会话打不开或反复报错，退出程序，用升级前的备份恢复 `%APPDATA%\AISTOC Agent` 后再启动。
- 不要在回滚过程中删除数据目录试图“重置”，那会永久丢失会话和密钥。

## 5. 版本归档建议

每个发布版本按目录归档，至少包含：

```text
releases/<version>/
├── AISTOC-Setup-<version>-x64.exe
├── build-info.json
└── SHA256SUMS.txt
```

建议同时保存该版本的验收记录和截图。升级或回滚时从归档目录取对应版本，避免把不同版本的安装包与校验文件混用。

## 6. 禁止事项

- 不要用来源不明或哈希不符的安装包升级、回滚。
- 不要先卸载再安装来“升级”，除非确实需要清理安装目录；卸载向导可能删除用户数据。
- 不要在升级或回滚过程中手动修改、移动或删除 `%APPDATA%\AISTOC Agent`。
- 不要把包含 API Key 的数据备份放到共享目录或通过普通聊天工具传输。
